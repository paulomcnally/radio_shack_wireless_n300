# PATCH-012: Implement CSRF Token Protection

**Vulnerability:** VULN-012 (No CSRF protection)
**Complexity:** High
**Requires Recompilation:** Yes (Boa + all HTML)
**Risk Level:** Medium

## Recommended Fix

Implement a per-session CSRF token generated by the Boa web server. The token must be embedded as a hidden field in every form and validated on each POST request. Sessions are identified by a secure, HTTP-only cookie.

## Implementation Approach

### 1. Session and Token Generation (Boa source)

In `boa/src/response.c` or a new `csrf.c` module:

```c
#include <openssl/rand.h>

/* Generate random CSRF token */
static int generate_csrf_token(char *token, size_t len) {
    unsigned char buf[32];
    RAND_bytes(buf, sizeof(buf));
    for (size_t i = 0; i < len / 2 && i < sizeof(buf); i++) {
        sprintf(token + i * 2, "%02x", buf[i]);
    }
    token[len] = '\0';
    return 0;
}

/* Store token in session (keyed by client IP + User-Agent hash) */
typedef struct csrf_session {
    char token[65];
    time_t created;
    struct csrf_session *next;
} csrf_session_t;

static csrf_session_t *sessions = NULL;

char *get_or_create_csrf_token(const char *client_id) {
    csrf_session_t *s = sessions;
    while (s) {
        /* Check if session exists and is not expired (< 30 min) */
        s = s->next;
    }
    /* Create new session with token */
    csrf_session_t *new_session = malloc(sizeof(csrf_session_t));
    generate_csrf_token(new_session->token, 64);
    new_session->created = time(NULL);
    new_session->next = sessions;
    sessions = new_session;
    return new_session->token;
}
```

### 2. Validate CSRF Token on POST (Boa source)

In `boa/src/cgi.c` or the form handler:

```c
int validate_csrf_token(request *req) {
    if (req->method != M_POST) return 0; /* Only validate POST */

    char *submitted = get_cgi_value(req, "_csrf_token");
    if (!submitted) return -1; /* Missing token */

    char *client_id = get_client_identifier(req);
    char *expected = lookup_csrf_token(client_id);
    if (!expected) return -1; /* No session */

    if (strcmp(submitted, expected) != 0) return -1; /* Mismatch */

    /* Invalidate token after use (one-time use) */
    remove_csrf_token(client_id);
    return 0;
}
```

### 3. Set Session Cookie in Response Headers

```c
void set_csrf_cookie(response *resp, const char *token) {
    char cookie_header[256];
    snprintf(cookie_header, sizeof(cookie_header),
        "Set-Cookie: _csrf_session=%s; Path=/; HttpOnly; SameSite=Strict",
        token);
    add_response_header(resp, cookie_header);
}
```

### 4. Add Hidden Fields to All HTML Forms

Every form in `/www/*.html` must include the CSRF token. Since tokens are dynamic, forms must be served as CGI-generated content or use server-side includes.

Example pattern for all forms:

```html
<form method="POST" action="/goform/setWireless">
+   <input type="hidden" name="_csrf_token" value="<% get_csrf_token(); %>" />
    <!-- existing form fields -->
    <input type="submit" value="Apply" />
</form>
```

### 6. JavaScript Token Injection (Alternative for Dynamic Forms)

If some forms are submitted via AJAX, inject the token via JavaScript:

```html
<script>
var csrfToken = '<%= get_csrf_token() %>';
// Attach to all AJAX submissions
</script>
```

## Verification

1. Inspect page source and confirm hidden `_csrf_token` fields are present in all forms.
2. Attempt to submit a form without the token and verify rejection:
   ```bash
   curl -X POST http://router/goform/setWireless -d "param=value"
   # Should return 403 Forbidden
   ```
3. Verify that replaying a used token is rejected.
4. Confirm that cross-origin form submissions are blocked (SameSite=Strict).
5. Test that HTTP-only cookie prevents JavaScript from reading the session token.

## Notes

- This is the highest complexity patch as it modifies the core web server and all HTML templates.
- All forms must be migrated to use the token; missing even one creates an attack vector.
- Consider using a compiled template system to inject tokens automatically rather than editing each HTML file.
- The session mechanism should be minimal to avoid memory leaks on an embedded system.
- If Boa cannot be easily modified, consider replacing it with a lightweight alternative that has CSRF support (see PATCH-014).
